## 1️⃣ 문제 정의 및 해결 방안

### 1.1 기존 경험 정리 기능의 문제

#### 1. 단발성
- 프로젝트가 이미 종료된 상황을 가정하고 대화 진행
- 공고에 지원하면서도 계속 경험을 쌓는 경우가 대부분인데, 계속해서 최신화 불가능, 아예 새로운 대화를 시작해야 함
- 한 번 대화하고 결과물을 받는 방식은 경험 정리의 목적에 부합하지 않음

**→ 지속적으로 기록하고 수정할 수 있는 구조로 변경**

#### 2. 사용자의 주도권 부족
- 수동적 사용자를 가정하고 대화 진행
- 정해진 질문과 체크리스트에서 벗어날 수 없고, 강제적
- 대화 진행 상태가 불명확
- 사용자의 답변에 대한 평가나 질문에 대한 응답 등 인터랙션이 불가능하여 답답함
- AI가 주체가 아닌, 필요한 순간 질문하고 정제해주는 보조 역할을 해야 함
- 단, 취준 초보 사용자도 쉽게 이용할 수 있도록 AI 기능 설계 필요

**→ 사용자가 필요할 때 AI의 보조를 받을 수 있는 구조로 변경**

#### 3. 텍스트 기반 결과물
- 사용자가 자신의 경험 구조를 시각적으로 파악하기 어려움
- 자기소개서, 포트폴리오, 직무 면접, 인성 면접 등 다양하게 이용하기에는 한계 존재

**→ 다양한 뷰 지원**

### 1.2 서비스 전반의 문제

#### 1. 서비스 타겟의 모호성
- 타겟인 대학생/취준생 안에서도 준비 단계별 니즈가 다름
- 현재 기능으로 커버되지 않는 준비 단계가 존재
- 사용자가 지금 자신에게 필요한 기능이 무엇인지 판단하기 어려움

**→ 상위 타겟은 유지하되, 준비 단계별로 핵심 기능과 메세지 분리**

#### 2. 유입 동기의 부족
- 서비스를 처음 사용하게 만드는 매력적인 입구가 없음
- 사용자는 현존하는 기능들의 필요성을 알지만, 급하지 않으면 사용을 미룸
- 경험 정리는 경험이, 포트폴리오 첨삭은 포트폴리오가 있어야 기능 사용을 시작할 수 있어, 조건을 충족하지 않으면 기능 사용 불가

**→ 사용자가 서비스를 처음 사용해 볼 수 있는 더 가볍고 매력적인 기능 추가**

#### 3. 접근성 취약
- 웹에 들어오고 로그인해서 쓰는 방식은 반복적인 사용에 불리함
- 사용자가 생각났을 때 바로 기록하거나 정리하기 어려움

**→ 카카오톡 알림톡/채널 메세지를 활용해 경험 정리 접근성 강화**

## 2️⃣ v.3 개편 전략 및 타겟

### 2.1 기능 개편 전략

#### 0. v.3에서 진행하지 않을 것
- 포트폴리오 외의 서류 전형 보조 기능 추가
  - e.g. 자기소개서 초안 생성, 자기소개서 첨삭
- 면접 전형 보조 기능 추가
  - e.g. 포트폴리오 기반 면접 질문 생성, 모의 면접, 면접 모범 답안 생성
- 포트폴리오 첨삭 기능 고도화
  - e.g. 구조화 없이 pdf 포트폴리오 첨삭, 첨삭 가이드 고도화, JD 추출
- 지원 상황을 기록하고 점검하는 기능 추가
  - e.g. 지원 현황 대시보드, 면접 복기 기능, 탈락 원인 분석 기능

#### 1. 인사이트 로그 → 제거
- 제거
  - 경험 중 얻는 인사이트는 경험 정리로 편입
  - 경험 외적으로 얻는 인사이트는 서비스 내에 기록 불가
- 이유
  - v.1에서 인사이트 로그를 도입한 목적이 프로젝트 진행 중에도 인사이트를 기록하여 이후 경험 정리에 쉽게 활용하도록 한 것
    → v.3에서는 경험 정리를 계속해서 수정할 수 있도록 개편하므로 목적성 소멸
  - 인사이트 로그의 목적과 의도를 사용자가 이해하지 못함
  - v.1의 기능 3가지 중 사용률 가장 저조

#### 2. 경험 정리 → 개편
- 완료의 개념 없이, 계속해서 수정 및 편집 가능
- 사용자가 직접 내용을 입력하고 편집 가능
- AI는 필요 시 사용자의 질문에 답변, 문구 정제 및 보완 등을 돕는 보조 역할로 사용
- 텍스트형 포트폴리오 뿐만 아니라 플로우차트, 표 등 여러 뷰로 경험 내용 표시
- 카카오톡 알림톡/채널 메세지를 활용해 접근성 강화
- v.2의 포트폴리오 시각화 기능은 향후 수정하여 경험 정리의 뷰로 활용

#### 3. 포트폴리오 첨삭 → 유지
- v.1의 핵심 기능 유지. 꼭 필요한 세부사항만 수정.

#### 4. 직무 찾기 → 추가
- 테스트 결과를 바탕으로 사용자에게 직무와 기업 형태를 추천해주는 기능
- 테스트는 Holland 흥미 유형 검사의 변형과 희망 근무 조건 밸런스 게임으로 구성

### 2.2 기능별 타겟 고객 및 페르소나

#### 1. 직무 찾기
**타겟 고객**
- 커리어 준비를 시작하고 싶지만 무엇부터 해야 할지 모르는 대학생/ 예비 취준생
- 아직 경험이나 포트폴리오는 없지만, 직무 탐색, 준비 방향 등에 대한 고민이 있는 사용자
- 본격적으로 취업 준비를 하기 전 단계에서 자신에게 잘 맞는 직무를 알고 싶은 사용자
**대표 페르소나**
- 2\~3학년 대학생
- 관심 있는 직무가 막연하거나 여러 개라서 좁히지 못함
- 아직 포트폴리오나 자기소개서에 쓸 만한 결과물은 없음
- “어떤 직무가 나에게 잘 맞을까?”, “어떤 경험을 쌓아야 할까?”를 궁금해 함
- 니즈: 직무 추천, 직무별 준비 방향 및 필요한 경험

#### 2. 경험 정리
**타겟 고객**
- 프로젝트, 대외활동, 인턴, 동아리 등 경험은 있지만 아직 이를 체계적으로 정리하지 못한 사용자
- 자기소개서와 포트폴리오 등 지원 서류 작성 전, 자신의 경험을 구조화해야 하는 사용자
- 진행 중인 활동을 계속 기록하고 나중에 취업 준비 자료로 활용하고 싶은 사용자
- 활동은 여러 개 했지만, 따로 기록해두지 않아 지원 서류 작성 시 기억에 의존하여 작성하는 사용자
**대표 페르소나**
- 4학년 대학생 또는 취준생
- 현재 행동: 노션이나 메모장에 활동 정보를 기록하거나, 지원 직전에 기억을 더듬어 정리함
- 페인포인트: 스스로 경험을 체계적으로 정리하기 어려움, 정제된 표현으로 기록하기 어려움, 산재된 기록을 모아서 정리하기 어려움
- 니즈: 자신의 경험을 체계적으로 정리하고, 지원 서류 작성 시 사용하고 싶음
- 사용 트리거: 본격적인 취준을 준비하는 시점, 경험 정리 없이 취준을 시작했다가 경험 정리의 필요성을 느낀 시점

#### 3. 포트폴리오 첨삭
**타겟 고객**
- 이미 포트폴리오 초안이 있거나, 경험을 정리해둔 취준생
- 실제 공고에 지원하고 있고, 지원할 공고에 딱 맞는 포트폴리오를 만들고 싶은 취준생
**대표 페르소나**
- 4학년 대학생, 취준생
- 현재 행동: 친구, 선배, 취업지원센터, AI에 피드백을 요청함
- 페인포인트: 자주 피드백을 받을 창구를 찾기 어렵고, 피드백 신뢰도가 의심되기도 함, 포트폴리오 수정 시간이 오래 걸려 지원이 지체됨
- 니즈: 지원하는 공고 기준으로 적합하거나 부적합한 내용을 파악하고 빠르게 보강하고 싶음
- 사용 트리거: 본격적인 취준 시작 이후 맞춤형 포트폴리오의 필요성을 느낀 시점

  - 포트폴리오 첨삭 결과 생성

  - 직무 찾기 결과 생성
  - 경험 정리 생성 또는 수정
