# 기획 문서 읽기

## 기준과 순서

README와 registry/updates.json에서 현재 업데이트를 확인한 뒤 해당 업데이트의 README·PRD·IA와 features의 기능 README를 읽습니다. 명세·화면 설명·공통 정책·결정 기록은 질문과 관련된 범위에서 함께 읽습니다.

main은 최신 승인 기획입니다. 작성 중인 PR은 미승인으로 구분합니다. 개발·배포 완료 상태는 별개입니다. 특정 승인 커밋·태그로 질문받으면 그 시점에서 같은 경로를 읽습니다.

## 현재·과거와 계승

features/에는 현재 승인 기능 문서를, updates/에는 업데이트별 독립 계획과 변경 목록을 둡니다. 현재 기능이 이전 업데이트 이후 수정되지 않았어도 유지 기능일 수 있습니다. 업데이트 목록에 없다는 이유로 폐기로 해석하지 않습니다.

완료된 업데이트의 기능·정책 링크는 당시 태그·승인 커밋으로 고정합니다. 과거 자료를 현재 요구사항으로 답하지 않습니다. 기능 상태의 유효·폐기와 업데이트 변경 유형의 신규·유지·수정·개편·폐기를 구분합니다.

## 정책·버전·ID

공통 정책이 기본이며 명시·승인된 기능 예외만 적용합니다. 문서가 충돌하면 양쪽 위치·적용 범위를 제시합니다. 수정 시각만으로 우선 문서를 고르지 않습니다.

와이어프레임 vM.m과 설명 vM.m.p의 앞 두 자리는 선택한 기능 기준으로 일치해야 합니다. 다른 기능만 바뀐 Figma 페이지를 본 기능의 새 승인본으로 간주하지 않습니다. 화면요소 ID는 Figma와 설명 양쪽의 표시를 확인합니다.

## 답변

질문의 답을 먼저 쓰고 문서 링크·사용한 버전 또는 커밋·필요한 화면 위치를 제시합니다. 명시된 사실, 제안, 미정 사항을 구분합니다. 근거가 없으면 미기록이라고 답합니다. 원문·코드를 읽지 않았으면 확인했다고 말하지 않습니다.

개발팀은 이 읽기 규칙을 자체 에이전트의 기획 조회에 연결합니다. 구현 방법·코드 스타일·테스트·배포 지침은 개발팀이 관리합니다.
